1 · Authentication

Every request must carry a valid API credential in the Authorization header.

API Key (recommended)
Authorization: Bearer <API_KEY>
OAuth 2.0 Token
Authorization: Bearer <ACCESS_TOKEN>

API keys can be generated in Settings → API Keys within the Coralogix console. Tokens expire after 1 hour; use the OAuth refresh flow for long-running processes.

2 · Regions & Base URLs

Substitute the base URL for your Coralogix region.

RegionBase URL
US (East)https://ng-api-http.coralogix.com
EU (West)https://ng-api-http.eu2.coralogix.com
Indiahttps://ng-api-http.app.coralogix.in
Singaporehttps://ng-api-http.coralogixsg.com

The cx CLI stores these per profile (cx profiles add) and applies the correct base URL automatically.

3 · Dashboard Catalog

CRUD operations for dashboard objects managed by the Coralogix Dashboard Service.

GET /mgmt/openapi/5/dashboards/dashboards/v1/catalog List all dashboards
🔑 Requires Bearer token

Returns a flat list of every dashboard the authenticated user can access, including name, folder, timestamps, and pin/lock state. Does not return widget definitions — use Get dashboard by ID for full content.

Query Parameters

ParameterTypeDescription
None

Response 200

{
  "items": [
    {
      "id":          "src7ykxHoM17HoxlEBB7W",
      "name":        "Production Overview",
      "description": "Main production dashboard",
      "slugName":    "production-overview",
      "createTime":  "2024-01-01T00:00:00Z",
      "updateTime":  "2024-06-15T12:00:00Z",
      "isDefault":   false,
      "isPinned":    true,
      "isLocked":    false,
      "folder": {
        "id":       "folder-01",
        "name":     "Engineering",
        "parentId": null
      }
    }
  ]
}

Response fields

FieldTypeDescription
itemsarrayList of dashboard catalog items.
items[].idstring?Unique dashboard identifier.
items[].namestring?Display name.
items[].descriptionstring?Human-readable description.
items[].slugNamestring?URL-safe identifier.
items[].createTimestring?ISO 8601 creation timestamp.
items[].updateTimestring?ISO 8601 last-update timestamp.
items[].isDefaultbool?Whether this is the account's default dashboard.
items[].isPinnedbool?Pinned to the navigation bar.
items[].isLockedbool?Locked against edits.
items[].folderobject?Parent folder (id, name, parentId), or null.
cx CLI
cx dashboards catalog  ·  cx dashboards catalog -o json  ·  cx -p prod-eu -p prod-us dashboards catalog
GET /mgmt/openapi/5/dashboards/dashboards/v1/{id} Get dashboard by ID
🔑 Requires Bearer token

Returns the full JSON definition of a single dashboard including all widgets, layout, and query expressions.

Path Parameters

ParameterTypeDescription
idrequiredstringDashboard identifier (from catalog.items[].id).

Response 200

// Full dashboard definition (schema varies by dashboard type)
{
  "id":          "src7ykxHoM17HoxlEBB7W",
  "name":        "Production Overview",
  "description": "...",
  "layout":      { /* widget layout tree */ },
  "variables":   [ /* template variables */ ],
  "filters":     [ /* dashboard-level filters */ ]
}
cx CLI
cx dashboards get <dashboard-id>  ·  cx dashboards get <id> -o json
POST /mgmt/openapi/5/dashboards/dashboards/v1 Create dashboard
🔑 Requires Bearer token

Creates a new dashboard from a full JSON definition. The requestId field is used for idempotency — re-submitting with the same ID within a short window will not create a duplicate.

Request Body

FieldTypeDescription
requestIdrequiredstringIdempotency key (16-char hex recommended). Generated automatically by cx.
dashboardrequiredobjectFull dashboard definition. Must contain a layout field.
dashboard.namestringDisplay name for the dashboard.
dashboard.layoutrequiredobjectWidget layout tree.
dashboard.folderIdobject?Target folder: {"value": "<folder-id>"}. Omit for root.

Example Request

{
  "requestId": "a3f1b2c4d5e6f708",
  "dashboard": {
    "name":     "My New Dashboard",
    "layout":   { "sections": [] },
    "folderId": { "value": "folder-engineering-01" }
  }
}

Response 200

{
  "dashboardId": "newDashboardXyz123"
}
cx CLI
cx dashboards create --from-file dashboard.json  ·  cx dashboards create --from-file dashboard.json --folder <folder-id>  ·  cat dash.json | cx dashboards create

4 · Dashboard Folders

Organise dashboards into a folder hierarchy. Folders can be nested via parentId.

GET /mgmt/openapi/5/dashboards/folders/v1 List all folders
🔑 Requires Bearer token

Returns every folder in the account. The top-level key is folder (singular).

Response 200

{
  "folder": [
    {
      "id":       "folder-engineering-01",
      "name":     "Engineering",
      "parentId": null
    },
    {
      "id":       "folder-backend-02",
      "name":     "Backend",
      "parentId": "folder-engineering-01"
    }
  ]
}
cx CLI
cx dashboards folders list  ·  cx dashboards folders list -o json
POST /mgmt/openapi/5/dashboards/folders/v1 Create folder
🔑 Requires Bearer token

Creates a new folder. Nest folders by providing parentId. Folder names must be unique within the same parent.

Request Body

FieldTypeDescription
requestIdrequiredstringIdempotency key.
folder.namerequiredstringFolder display name.
folder.parentIdoptionalstringID of the parent folder. Omit to create a top-level folder.

Example Request

{
  "requestId": "b4c2d1e5f6a70823",
  "folder": {
    "name":     "Infrastructure",
    "parentId": "folder-engineering-01"
  }
}

Response 200

{ "folderId": "folder-infra-03" }
cx CLI
cx dashboards folders create --name "Infrastructure"  ·  cx dashboards folders create --name "Sub" --parent-id <folder-id>

5 · Dashboard Knowledge Base Search

Semantic search endpoints powered by vector embeddings. The gateway prefix /api/v1/olly-kb/ routes to the knowledge-base service. Results are ranked by cosine similarity. Limits are clamped to 1–100.

GET /api/v1/olly-kb/dashboards/queries/search Search dashboard queries
🔑 Requires Bearer token

Semantic search over individual widget queries and expressions stored across all dashboards. Returns the most similar widget queries to your natural-language description, ranked by similarity score. Useful for finding which dashboards already monitor a particular signal.

Query Parameters

ParameterTypeDescription
query_textrequiredstringNatural-language description of the query to find. E.g. http error rate by service. Must not be empty. URL-encoded.
limitoptionalintegerMaximum results to return. Range: 1–100. Default: 10.

Response 200

{
  "results": [
    {
      "query_text":       "rate(http_requests_total[5m])",
      "similarity":      0.93,
      "dashboard_name":  "API Overview",
      "dashboard_folder":"Engineering",
      "widget_title":    "Request Rate",
      "widget_type":     "lineChart",
      "query_context":   "Monitors request rate over 5 min",
      "extracted_fields": ["http_requests_total"]
    }
  ]
}

Response fields

FieldTypeDescription
results[].query_textstringThe raw widget query expression (PromQL, DataPrime, etc.).
results[].similarityfloatCosine similarity score (0.0–1.0). Higher = closer match.
results[].dashboard_namestring?Name of the containing dashboard.
results[].dashboard_folderstring?Folder the dashboard belongs to.
results[].widget_titlestring?Title of the widget containing the query.
results[].widget_typestring?Widget visualization type (e.g. lineChart, datatable).
results[].query_contextstring?Human-readable description of what the query monitors.
results[].extracted_fieldsstring[]Field names referenced in the query.
cx CLI
cx dashboards search "http error rate"  ·  cx dashboards search "cpu usage over time" --limit 20 -o json
GET /api/v1/olly-kb/dashboards/semantic-search Semantic dashboard search
🔑 Requires Bearer token

Find dashboards by semantic similarity to a natural-language description. Matches against dashboard names, descriptions, and auto-generated semantic summaries. Returns whole-dashboard objects rather than individual widget queries — use this to discover relevant dashboards, and search queries to inspect specific widget expressions.

Query Parameters

ParameterTypeDescription
query_textrequiredstringNatural-language description. E.g. kubernetes pod memory usage. Must not be empty. URL-encoded.
limitoptionalintegerMaximum results to return. Range: 1–100. Default: 10.

Response 200

{
  "results": [
    {
      "dashboard_id":         "abc-123",
      "dashboard_name":       "Kubernetes Overview",
      "dashboard_folder":     "Infrastructure",
      "description":         "Pod memory and CPU usage",
      "semantic_description": "Monitors Kubernetes pod resource consumption",
      "widget_count":         8,
      "similarity":           0.91
    }
  ]
}

Response fields

FieldTypeDescription
results[].dashboard_idstringUnique dashboard ID. Use with Get dashboard by ID.
results[].dashboard_namestring?Display name.
results[].dashboard_folderstring?Containing folder name.
results[].descriptionstring?User-authored description.
results[].semantic_descriptionstring?Auto-generated semantic summary of dashboard content.
results[].widget_countintegerNumber of widgets in the dashboard.
results[].similarityfloatCosine similarity score (0.0–1.0).
cx CLI
cx dashboards semantic-search "kubernetes pod memory"  ·  cx dashboards semantic-search "http error rate" --limit 5 -o json
GET /api/v1/olly-kb/queries/by-field Queries by field path
🔑 Requires Bearer token

Returns all dashboard widget queries that reference a specific DataPrime field path. Use this to understand the blast radius of a schema change — which dashboards will break if $d.http.status is renamed?

Query Parameters

ParameterTypeDescription
field_pathrequiredstringDataPrime field path to look up. E.g. $d.http.status, $l.severity. Must not be empty.
limitoptionalintegerMaximum results to return. Range: 1–100. Default: 10.

Response 200

{
  "queries": [
    {
      "query_text":     "filter $d.http.status == 500",
      "dashboard_name": "Error Monitor",
      "widget_title":   "5xx Errors",
      "matched_fields": ["$d.http.status"]
    }
  ]
}

Response fields

FieldTypeDescription
queries[].query_textstringThe raw widget query expression.
queries[].dashboard_namestring?Name of the containing dashboard.
queries[].widget_titlestring?Title of the widget.
queries[].matched_fieldsstring[]Which field paths in the query matched the lookup.
cx CLI
cx dashboards queries-by-field "$d.http.status"  ·  cx dashboards queries-by-field "$l.severity" --limit 20 -o json

6 · Field Value Search

Fuzzy-match field keys by the values they store. Answers the question: "which fields contain the value 404?" Routes to the values-reader-service.

POST /api/v1/search-by-value Search fields by value
🔑 Requires Bearer token

Returns field keys whose stored values fuzzy-match the given query string. Similarity is scored 0.0–1.0 with 1.0 indicating an exact match. Useful for discovering the correct field name when you only know the value it should contain.

Request Body (JSON)

FieldTypeDescription
queryrequiredstringValue string to search for. E.g. "404", "production". Must not be empty.
dataset_typerequiredstringDataset scope: "logs", "spans", or "all".
limitoptionalintegerMaximum results. Range: 1–100. Default: 10.
offsetoptionalintegerPagination offset. Default: 0.

Example Request

{
  "query":        "404",
  "dataset_type": "logs",
  "limit":        10,
  "offset":       0
}

Response 200

{
  "matches": [
    {
      "key_matched":     "$d.http.status",
      "value":           "404",
      "similarity_score": 1.0
    },
    {
      "key_matched":     "$d.response_code",
      "value":           "404",
      "similarity_score": 0.95
    }
  ],
  "total_hits": 2
}

Response fields

FieldTypeDescription
matches[].key_matchedstringField key that matched (DataPrime path, e.g. $d.http.status).
matches[].valuestringThe stored value that matched the query.
matches[].similarity_scorefloatMatch confidence (0.0–1.0; 1.0 = exact).
total_hitsintegerTotal number of matching keys before limit/offset.
cx CLI
cx search-by-value "404"  ·  cx search-by-value "production" --dataset spans  ·  cx search-by-value "error" --dataset all --limit 20 -o json

7 · Error Codes

All error responses return JSON with a message field describing the failure.

StatusMeaningCommon Causes
400 Bad Request Missing required field, invalid JSON, empty query_text or field_path.
401 Unauthorized Missing, expired, or invalid API key / OAuth token.
403 Forbidden Valid credentials but insufficient permissions for the requested resource.
404 Not Found Dashboard ID does not exist in the account.
500 Internal Server Error Upstream service failure. Retry with exponential back-off.
503 Service Unavailable Maintenance window or overload. Retry after a few seconds.

Example Error Response

{
  "message": "Invalid or expired API key"
}
